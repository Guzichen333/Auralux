# Auralux Next Stage Design

## Goal

Move Auralux from UI-NEXT migration mode into a verified product stage: UI-NEXT is the default and only user-facing shell, settings are fully Chinese, startup work is staged behind a dynamic splash experience, cover loading stops repeating expensive remote fetches, NetEase account status feels first-class, and old UI removal is planned from evidence before deletion.

## Non-Negotiables

- Do not reset, clean, checkout, or overwrite existing uncommitted work.
- Do not edit generated `src/renderer/public/**` by hand.
- Do not reduce the current playback page quality, immersive player motion, lyric behavior, cover treatment, or visual feel.
- Do not add lyric translation or bilingual lyric comparison.
- Do not delete old UI code until its dependencies are classified and the user confirms deletion.
- Every stage must update `docs/progress/auralux-next-stage.md` with files changed, verification commands, results, risks, and next steps.
- Every source edit must follow GitNexus impact analysis for the touched symbol before editing.
- Every stage must use real verification: scripts, typecheck, builds, GitNexus `detect_changes`, and dev app restart when UI is involved.

## Current Evidence

- UI-NEXT source lives in `src/renderer/ui-next-static/**` and bridge code lives in `src/renderer/src/ui-next/**`.
- Generated UI-NEXT runtime output lives in `src/renderer/public/ui-next/**`; it must be regenerated by `npm run build:renderer`.
- `src/renderer/src/app/bootstrap/main.ts` still supports legacy UI startup through `legacy-ui` and `legacyui`.
- `src/renderer/src/ui-next/bootstrap.ts` still exposes `__disableMusicBoxUINext`.
- `src/renderer/ui-next-static/NewMusicShell.js` still has a "return to old UI" action.
- UI-NEXT still reuses some old UI components: `NetEaseCloudMusic`, `AddToPlaylistDialog`, `CreatePlaylistDialog`, `NetworkDiskModal`, and `PluginManagerModal`.
- The previous settings localization plan file exists but is not safe to execute directly because terminal output shows corrupted Chinese text.

## Stage 1: Settings UI Chinese Localization and Readability

Translate only visible UI text:

- UI-NEXT settings section titles, labels, descriptions, buttons, empty states, loading states, and action cards.
- Settings-related toasts, confirm dialogs, shortcut state text, cache state text, and directory state text.

Keep these unchanged:

- Internal setting keys.
- DOM IDs.
- CSS class names.
- IPC names.
- Logs and comments unless they are shown to users.
- Technical names such as Auralux, WASAPI, DevTools, Electron, UI-NEXT, Windows, and px.

Add a verification script `scripts/verify-settings-ui-chinese.js` that fails when known visible English settings strings remain. Add danger styling for destructive settings actions and wrapping rules for long Chinese labels.

## Stage 2: UI-NEXT Formalization

Make UI-NEXT the only user-facing shell:

- Remove the UI-NEXT action that switches back to the old UI.
- Disable legacy query switching from user-facing startup.
- Keep old UI components that UI-NEXT still imports until they are migrated.
- Add a guard script that proves the legacy switch path is gone from user-facing code while allowing internal audit docs to mention it.

## Stage 3: Dynamic Startup Page and Background Warmup

Introduce a dynamic startup experience before the main shell becomes interactive. Startup work should run concurrently where safe:

- Load settings.
- Load local library snapshot.
- Restore queue or playback context where available.
- Check NetEase login state and account profile.
- Check NetEase API connectivity without blocking local playback.
- Load cover cache index.
- Load lyric cache index when available.
- Detect pending sync or migration work.

Startup rules:

- Minimum visible splash time: about 1 second.
- Maximum blocking wait: about 4 to 6 seconds.
- Timeout enters UI-NEXT and continues non-critical work in the background.
- NetEase failure must surface as a degraded state, not a startup blocker.

## Stage 4: Cover Cache Performance

Prevent playlist entry from repeatedly fetching the same cover assets:

- Maintain a cover cache manifest keyed by stable cover source data.
- Use existing cached cover paths before remote fetch.
- Fetch only when missing, corrupt, or the cover source changes.
- Deduplicate concurrent requests for the same cover.
- Limit concurrent downloads.
- Use retry backoff on failure.
- Preserve playback page visual behavior.

Verification must include evidence that entering the same playlist twice does not perform a repeated full cover fetch.

## Stage 5: NetEase Account Center

Make the account state feel like a first-class part of the product:

- Show avatar and nickname.
- Show login state.
- Show last sync time.
- Show current sync state.
- Show retry entry for failed account or sync state.
- Preserve the existing avatar behavior.

The UI must handle logged-in, logged-out, and failure states.

## Stage 6: Old UI Source Audit and Deletion Plan

Do not delete old UI immediately. Classify old UI files into:

- Safe to delete now.
- Still reused by UI-NEXT and must be migrated before deletion.
- Still required by plugin, API, or compatibility boundaries and must be deferred.

The audit must include `rg` evidence and type/build verification. Deletion requires a separate user confirmation after the classification is written to the progress log.

## Verification Strategy

Every implemented stage must run the stage-specific checks plus:

- `npm run typecheck:renderer`
- `npm run build:renderer`
- `npm run build:ts`
- GitNexus `detect_changes({repo: "MusicBox", scope: "unstaged"})`

UI stages must restart the dev app and ask the user to manually verify the visible UI. The assistant must not perform the user's real click-through as final proof.

## Completion Definition

The goal is complete only when all six stages are implemented or intentionally paused by explicit user instruction, all required logs are updated, all verification evidence is fresh, the dev app is running for manual checks, and a final review confirms there are no unverified requirements.
